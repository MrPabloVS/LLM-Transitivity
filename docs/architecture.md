# Experiment architecture

The installed `llm_transitivity` package contains the experiment implementation.
The installed `transitivity` command replaces the root Python adapters.
The historical runner and benchmark inputs remain outside the package.

## Responsibilities

- `domain`: cases, model catalog, execution policy, selection and response interpretation.
- `datasets`: file validation, source comparison, pilot preparation and verification.
- `evidence`: JSON representations, hashes and source metadata.
- `openrouter`: HTTP capture, credential redaction and generation lookups.
- `inspect`: tasks, solvers, scoring metrics and Flow configuration.
- `runs`: result archives, exports and run execution.
- `costs`: price queries and estimates from verified inputs.
- `cli`: argument parsing and application composition.

Domain imports have no filesystem, Git, HTTP or Inspect dependencies. JSON
serialization and hashes use the same representations as the original manifest.
Framework adapters translate the domain values into Inspect objects.

## Source verification

Dataset operations receive an explicit repository root. They compare all source
records with the pinned Git revision and reproduce the original pilot bytes.
Complete dataset adaptation also checks the preserved main revision before
constructing Inspect samples. It reuses the full-record comparison rules and
retains provenance for every original row. The pilot keeps its existing manifest
and source anchor. General hashing and JSON functions live in `evidence`, not
in the preparation CLI.
Run provenance includes the project configuration and all Python sources inside
the package. It excludes credentials, unrelated files and generated bytecode.

## OpenRouter boundary

The OpenRouter client retains full redacted lookup payloads. The transport
capture records each HTTP attempt. Inspect solvers connect these components to
evaluation state. Lookup failures remain separate from model answers and usage.

## Inspect boundary

Task factories take the repository root explicitly. Flow specifications retain
that root as a task argument, so worker processes read the same inputs. Sample
UIDs, source row numbers and labels retain their previous meaning. The installed CLI uses the package task and Flow factories directly. Module
imports do not build specifications.

## Managed runs

CLI modules parse arguments and load credentials. The runner executes Flow; the
archive component freezes evidence before execution and indexes partial results
afterward. The exporter retains native model events and creates new files.
The `transitivity` command delegates to the selected CLI module.

A run failure remains the primary exception if finalization also fails. The
secondary error type is reported separately without its message. If execution
succeeds but finalization fails, the command fails. Export failures keep the
written log index and also fail finalization.

Managed tasks use a generation solver with a bounded capture context. It resets
the context on success, error and cancellation while retaining captured attempts
in sample metadata. Concurrent samples have separate contexts. The capture
component owns the context; metadata collection does not modify it.

## Cost estimates

The estimator verifies inputs, reads the shared domain policy and requests only
public provider quotes. Price retrieval selects the exact endpoint tag without
interpreting its status. Live access belongs to preflight verification.
Price retrieval is separate from arithmetic. It creates
no Inspect tasks or run identity. Reports keep the existing hash field names
and use package source paths for the estimator, Flow configuration and model
catalog. They also record hashes of the complete package implementation.
The cost archive component saves each complete estimate under a new
`results/cost_estimates/<local-date-time>-<id>/estimate.json` path. A directory
collision fails instead of replacing a previous capture. The CLI prints the new
snapshot path. Use [the cost procedure](pilot_costs.md) for new estimates.

## Verification

Use `uv sync --locked` to install the editable package. Build distributions with
`uv build`. Dataset verification uses `uv run --locked transitivity datasets verify`.
Preview both modes with `uv run --locked transitivity pilot --dry-run` and
`uv run --locked transitivity pilot --preflight --dry-run`.

Tests cover source preservation, source-label agreement, mocked provider quotes,
mocked HTTP retries, failed and cancelled generations, concurrent sample capture,
archive failures, import side effects and execution outside the repository.
Original log files and historical reports retain their original implementation
paths and scores. Package paths in new specifications identify the refactored
implementation; task arguments also record the explicit repository root.

The full-corpus verifier reproduces the existing generated inventory bytes.
The inventory retains its original command text for this check. Use installed
commands for current operations. Current readiness belongs in the pilot guide.

## Test responsibilities

The test folders follow the component boundaries:

- `tests/datasets`: record validation, corpus coverage, and pilot evidence protection.
- `tests/inspect`: sample adaptation, source fidelity, scoring, Flow, and SDK capture.
- `tests/openrouter`: generation lookups, retry records, and credential redaction.
- `tests/runs`: result archives, finalization, and error precedence.
- `tests/costs`: arithmetic, fixed endpoint quotes, estimates, and estimate archives.
- `tests/cli`: command dispatch, help, and repository selection.
- `tests/test_package.py`: import boundaries and execution outside the repository.

`tests/paths.py` locates the repository once. Shared mock run specifications are
function-scoped fixtures in `tests/conftest.py`. They create independent mutable
state and import Inspect only when used. Source mutation tests share an isolated
repository fixture under `tests/inspect/conftest.py`. HTTP response construction
lives in `tests/support/http.py`; test modules do not import other test modules.
Expected routes, prices, targets, and provenance assertions stay in the tests
that check them. Fixtures prepare inputs; they do not calculate expected results.

Run the full suite with `uv run --locked pytest`. To check one responsibility,
pass its directory, for example `uv run --locked pytest tests/openrouter`.
The tests use mock models and HTTP responses, not paid model requests.


## Installed commands

```sh
uv run --locked transitivity --help
uv run --locked transitivity datasets verify
uv run --locked transitivity pilot --dry-run
uv run --locked transitivity costs
uv run --locked transitivity export results/pilot/<run-directory>
```

`costs` requests public quotes and writes a new estimate snapshot. `pilot` requests model
responses unless `--dry-run` is set. Use each subcommand's `--help` to inspect
its options without loading credentials or performing the action.

The CLI finds the project from the current directory or its parents. From
another directory, select the project and set the root before the subcommand:

```sh
uv run --locked --project /path/to/repository transitivity --root /path/to/repository pilot --dry-run
```

Only the historical `runBenchmark.py` remains as Python code in the root.
Historical generated inventories, logs and reports keep their original command
text and source paths. Use the installed commands above for new work.
