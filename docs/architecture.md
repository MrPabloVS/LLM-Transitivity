# Experiment architecture

The installed `llm_transitivity` package contains the experiment implementation.
Root scripts keep the existing commands and public imports available.
The historical runner and benchmark inputs remain outside the package.

## Responsibilities

- `domain`: cases, model catalog, execution policy, selection and response interpretation.
- `datasets`: file validation, source comparison, pilot preparation and verification.
- `evidence`: JSON representations, hashes and source metadata.
- `openrouter`: HTTP capture, credential redaction and generation lookups.
- `inspect`: tasks, solvers, scoring metrics and Flow configuration.
- `runs`: result archives, exports and run execution.
- `costs`: price queries and estimates from verified inputs.
- `cli`: argument parsing and application composition.

Domain imports have no filesystem, Git, HTTP or Inspect dependencies. JSON
serialization and hashes use the same representations as the original manifest.
Framework adapters translate the domain values into Inspect objects.

## Source verification

Dataset operations receive an explicit repository root. They compare all source
records with the pinned Git revision and reproduce the original pilot bytes.
General hashing and JSON functions live in `evidence`, not in the preparation CLI.
Run provenance includes the root entry scripts and all Python sources inside the
package. It excludes credentials, unrelated files and generated bytecode.

## OpenRouter boundary

The OpenRouter client retains full redacted lookup payloads. The transport
capture records each HTTP attempt. Inspect solvers connect these components to
evaluation state. Lookup failures remain separate from model answers and usage.

## Inspect boundary

Task factories take the repository root explicitly. Flow specifications retain
that root as a task argument, so worker processes read the same inputs. Sample
UIDs, source row numbers and labels retain their previous meaning. Root task and
Flow modules adapt the old signatures to the package. Importing `flow.py` does
not build a specification; the Flow loader evaluates it in its execution context.

## Managed runs

CLI modules parse arguments and load credentials. The runner executes Flow; the
archive component freezes evidence before execution and indexes partial results
afterward. The exporter retains native model events and creates new files.
Existing root commands delegate to these components without changing arguments.

A run failure remains the primary exception if finalization also fails. The
secondary error type is reported separately without its message. If execution
succeeds but finalization fails, the command fails. Export failures keep the
written log index and also fail finalization.

Managed tasks use a generation solver with a bounded capture context. It resets
the context on success, error and cancellation while retaining captured attempts
in sample metadata. Concurrent samples have separate contexts. Legacy pre-hook
exports remain available for compatibility; managed tasks use the bounded solver.
